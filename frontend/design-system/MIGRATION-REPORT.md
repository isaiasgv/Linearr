# Design System Migration Report — Linearr

_Generated by /setup-design-system on 2026-07-19_

## Summary

- **Source system detected:** `foreign-css-vars` — the `@theme` block in
  `src/index.css` was a **palette-ramp** scheme (`--color-brand-*`,
  `--color-galaxy*`, `--color-success-*`, `--color-danger-*`, `--color-warning-*`,
  `--text-2xs`), not shadcn semantic tokens. Components consume the ramps as raw
  Tailwind palette utilities.
- **Migration mode:** **additive** (per setup choice). The shadcn semantic token
  layer (`:root` / `.dark` / `@theme inline`) was added **alongside** the existing
  ramps — no ramp was removed, so nothing that referenced them broke.
- **Brand:** kept the app's own indigo `#6366f1` as `--primary` (not re-skinned to
  Oribion blue). `--oribion` (`#176bff`) is present only as the mode-invariant
  family badge.
- **Mode:** light **and** dark defined; the FOUC-safe script was added to
  `index.html` and `<html class="dark">` was removed so the app now respects
  `localStorage` / OS preference (dark remains the default when nothing is saved).
- Tokens added: **27** (semantic color tokens) · Dark pairs: **26**
  (`--oribion` is invariant) · Unmapped / needs review: **0** ·
  Raw-palette occurrences catalogued: **~1,580** (see below).

> ⚠️ **Light mode is infrastructural only right now.** The token system, the FOUC
> script, and the `setTheme()` helper are wired, but ~1,580 component utilities
> still hardcode `bg-slate-*` / `text-slate-*` / `border-slate-*` and
> `indigo/purple`. Until those are migrated to the semantic utilities, toggling to
> light mode will leave most surfaces dark. Page chrome (`<body>`) responds
> correctly; individual components do not yet. Migrate incrementally using the
> catalog below.

## Needs review (no confident mapping)

_None._ The additive migration kept every existing token; nothing was dropped.

The existing palette ramps (`--color-brand-50…950`, `--color-success-*`,
`--color-danger-*`, `--color-warning-*`, `--color-galaxy*`, `--color-slate-750`,
`--text-2xs`) are **retained** in the `@theme` block. Remove them only once no
component references them (they currently power ~1,580 utilities — see below).

## What changed on disk

- `src/index.css` — added `@custom-variant dark`, `:root` + `.dark` semantic
  tokens, `@theme inline` mapping + type/radius/motion scales, a `body` base rule,
  and a global reduced-motion block. Existing ramps + base rules kept.
- `index.html` — added the FOUC-safe theme script; removed `class="dark"` from
  `<html>`; `<body>` now uses `bg-background text-foreground`; splash background
  uses `var(--background, #020617)`.
- `src/shared/lib/theme.ts` — **new** `setTheme` / `getTheme` / `isDark` helpers
  for wiring a light/dark toggle.
- `src/shared/components/ui/StateExample.tsx` — **kept** (already a complete
  four-state reference with a TanStack Query adapter).
- `design-system/` — showcase replaced with the QIIUB sidebar template
  (`showcase.html`, `showcase-build.mjs`, `README.md`, `DESIGN-SYSTEM.md`,
  `mockups/dashboard.html`); `showcase:build` wired into `package.json` and run
  once (`tokens.json` generated, TOKENS block synced from `src/index.css`).
  `showcase-build.mjs`'s candidate list was extended with `../src/index.css`
  because Linearr's Tailwind entry is `index.css`, not `app.css`.

## Next steps

1. Migrate `src/shared/components/ui/` and `layout/` primitives to semantic
   utilities first (highest coverage). Verify each in both themes.
2. Once no component references a palette ramp, remove the retained
   `--color-brand-*` / `--color-galaxy*` / status ramps from `@theme`.
3. Add a `ThemeToggle` using `@/shared/lib/theme` so users can switch modes.
4. Re-run the `design-system-auditor` before release to confirm compliance.
